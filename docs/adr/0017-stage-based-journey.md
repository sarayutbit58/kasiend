# Stage-Based Journey: เรียงเครื่องมือตามลำดับที่ควรเริ่ม

## Decision
เปลี่ยนโครงสร้างหน้าเว็บจาก "3 กล่องคำนวณเรียงกัน" เป็น **Stage-Based Journey** — 3 ขั้นตอนที่มีลำดับชัดเจน แต่ละขั้นอธิบายด้วยภาษาธรรมดาสำหรับผู้ใช้ไม่มีความรู้การเงิน

## Stages
| Stage | ชื่อ (ภาษาง่าย) | เครื่องคำนวณ | คำถามนำ |
|---|---|---|---|
| 1 🛡️ | ตั้งกำแพงกันภัย | เงินสำรองฉุกเฉิน | "ถ้าพรุ่งนี้งานหาย — มีเงินพออยู่ได้กี่เดือน?" |
| 2 📈 | ให้เงินทำงาน | ดอกเบี้ยทบต้น | "เงินที่เหลือจากรายจ่าย — ลงทุนแล้วเติบโตแค่ไหน?" |
| 3 🎯 | มองเป้าหมายไกล | เป้าเงินเกษียณ | "ออมแบบนี้ไปจนเกษียณ — จะมีเงินพอใช้ไหม?" |

## หลักการ
- **ลำดับคือเหตุผล**: Stage 1 = รากฐานที่ขาดไม่ได้ → Stage 2 = เมื่อมีรากฐานแล้วจึงเริ่มทำให้เงินเติบโต → Stage 3 = เป้าหมายปลายทางระยะยาว
- **ภาษาธรรมดา**: ไม่มีศัพท์บัญชี/การเงินที่ซับซ้อน — ผู้ใช้ไม่มีความรู้การเงินต้องเข้าใจได้ว่าทำไมต้องเริ่มที่ Stage 1
- **เชื่อมโยงระดับ UX เท่านั้น (ไม่ใช่ data pipeline)**: ป้าย Stage, คำอธิบาย transition, ข้อความ "เมื่อคุณทำ Stage 1 เสร็จ..." — ไม่เชื่อมข้อมูลระหว่างเครื่องมือใน v1.3 (จะทำในเฟสถัดไปเมื่อมีผู้ใช้จริงให้ feedback)
- **Single-page scroll หน้าเดียว**: คงโครงสร้างหน้าเดียวเลื่อนลง ไม่เปลี่ยนเป็น wizard หลายหน้า (รักษาความเรียบง่าย)
